# Security policy

## Supported versions

Only the latest tagged public release will receive security fixes after the
first archival release. This pre-release candidate is not yet a supported
production service.

## Reporting a vulnerability

Do not disclose credentials, private datasets, path traversal issues, unsafe
file-deletion behavior, or dependency vulnerabilities in a public issue before
the maintainer has had an opportunity to assess them. Use the repository's
private vulnerability-reporting channel after it is enabled, or contact the
corresponding author through the address published with the final paper.

Include the affected version/commit, operating system, minimal reproduction,
impact, and whether private research data could be exposed. Never attach real
tokens or confidential input files.

## Research-code boundary

The repository is not a hosted clinical, diagnostic, or production chemistry
service. Scientific validity concerns should be reported separately from
software security issues, but both should include reproducible evidence.
